---
title: Custom Error Pages
description: Serve custom HTML error pages for HTTP status codes and unmatched routes
---

GoDoxy serves custom HTML error pages from `/app/error_pages` whenever a route is not found, a domain does not match `match_domains`, or an upstream returns an error status outside `200–299` (for `text/html`, `application/xhtml+xml`, or `text/plain` responses).

## Setup

1. Create an `error_pages/` folder beside `compose.yml` and mount it to `/app/error_pages:ro` (already configured in `compose.example.yml`):

```yaml
services:
  app:
    image: ghcr.io/yusing/godoxy:latest
    container_name: godoxy-proxy
    network_mode: host # do not change this
    volumes:
      - ./config:/app/config
      - ./error_pages:/app/error_pages:ro
```

2. Place HTML files named `<statusCode>.html` directly in `error_pages/` (**subdirectories are not scanned**):

```plaintext
error_pages/
├── 403.html
├── 404.html
├── 500.html
├── 502.html
├── 503.html
└── style.css
```

Changes to files in `error_pages/` hot-reload automatically.

## Referencing CSS, JS, and Images

Prefix all local asset URLs with **`/$gperrorpage/`** so they load regardless of the requested path:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>404 — Not Found</title>
    <link rel="stylesheet" href="/$gperrorpage/style.css" />
    <script src="/$gperrorpage/app.js" defer></script>
  </head>
  <body>
    <h1>404</h1>
    <p>The requested page was not found.</p>
    <a href="/">Go Home</a>
  </body>
</html>
```

## Lookup Order

1. Exact match: `<statusCode>.html` (e.g. `502.html`)
2. Fallback: `404.html`
3. Original response if neither file exists

Custom error pages are enabled globally on the entrypoint by default. To attach them selectively via middleware, see [Custom Error Pages Middleware](../advanced-topics/middlewares/traffic-control/Custom-Error-Pages).
