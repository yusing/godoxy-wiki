## How GoDoxy Works

GoDoxy discovers your services and builds reverse proxy routes automatically:

1. **Docker & Podman containers**: GoDoxy watches your container runtime, reads each container's name, labels, and exposed ports, and creates routes live.
2. **Non-Docker services (VMs, Proxmox LXCs, bare-metal)**: Define routes in YAML files under `config/` and list them under `providers.include` in `config/config.yml`.

By default, a Docker container is reachable at **`<container_name>.yourdomain.com`**. Override the subdomain (or assign multiple subdomains / full FQDNs) with `proxy.aliases` — see [Configuring Routes](Configuring-Routes).

## Secure your containers

<Callout type="info">
  GoDoxy will work without mapping ports to the host.
</Callout>

Remove `ports` section in your `docker-compose.yml` file.

Doing this will make your host has only **one** exposed service, which is GoDoxy.

## Auto-Discovery & Behaviors

**Default URL: `<container_name>.yourdomain.com`**

### Container Proxying

GoDoxy proxies **all running containers** by default, **unless any of the following is true**:

- The label `proxy.exclude` includes **proxy** (`true`, `proxy`, or `all`)
- The container belongs to a Docker provider in **explicit-only mode** (provider name with a trailing `!`, e.g. `local!: $DOCKER_HOST`)
- The container is a backend-only service (e.g. headless browsers, databases)
- The container has no exposed port
- The container name starts with `buildx_`
- The alias starts with `x-` or ends with `-old`

### Explicitly Enable Container Proxying

When a Docker provider is in explicit-only mode (`local!`), set **any** label starting with `proxy.` (for example `proxy.aliases: myapp`) to include the container.

### Health Monitoring

Health monitoring is enabled by default for **all containers**, including excluded ones.

Docker healthchecks are preferred when available. Disable GoDoxy's fallback probe per route with `healthcheck.disable: true` in a route file or Docker label, or for every route of a container with `proxy.exclude: healthcheck`. Use `proxy.exclude: proxy,healthcheck` or `proxy.exclude: all` to exclude both proxying and GoDoxy health probing (`proxy.exclude: true` excludes only proxying). See [Health Monitoring](../advanced-topics/Health-Monitoring).

```yaml
services:
  app:
    labels:
      proxy.exclude: all
```

## Authentication

<Callout type="warn">
  To use the WebUI without HTTPS, set `GODOXY_API_JWT_SECURE=false` in `.env`.
  **Not recommended** for production unless an external proxy terminates TLS in
  front of GoDoxy.
</Callout>

#### User Password Auth

Set both `GODOXY_API_USER` and `GODOXY_API_PASSWORD` in `.env` when using username/password authentication. GoDoxy rejects startup when either value is missing unless OIDC is enabled or authentication is explicitly disabled.

#### OpenID Connect (OIDC)

Use an external identity provider (Pocket ID, Authentik, Keycloak, etc.) for WebUI SSO and per-app authentication. See [OIDC Configuration](OIDC).

## Environment Variables & Provider Recovery

See [Environment Variables](Environment-Variables) for the complete generated setting table, defaults, prefix migration, and startup diagnostics. Copy `.env.example` to `.env`, configure credentials, and uncomment only overrides. Compose uses `socket-proxy` and passes the configured Docker endpoint unchanged.

### Configuration Interpolation

Use braces for environment references in YAML, for example:

```yaml
providers:
  docker:
    local: unix://${DOCKER_SOCKET}
```

References work both as whole values and inside strings; missing variables fail validation. The exact Docker provider value `$DOCKER_HOST` is a special shorthand that reads `GODOXY_DOCKER_HOST` (defaulting to `unix:///var/run/docker.sock`); other bare `$VAR` references in Docker endpoints are rejected.

### Automatic Provider Recovery

Unavailable Docker and agent providers retry startup automatically with backoff from 3 to 30 seconds and are reported as degraded while retrying. A successful retry reloads routes without requiring a container event or config save. A config reload or shutdown cancels pending retries.
