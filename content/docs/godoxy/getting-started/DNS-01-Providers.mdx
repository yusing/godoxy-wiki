## Supported provider IDs

GoDoxy bundles these 30 Lego DNS integrations:
`acmedns`, `azuredns`, `cloudflare`, `cloudns`, `clouddns`, `desec`,
`digitalocean`, `dnsupdate`, `duckdns`, `edgedns`, `gcloud`, `godaddy`,
`hetzner`, `hostinger`, `httpreq`, `infomaniak`, `inwx`, `ionos`, `linode`,
`namecheap`, `netcup`, `netlify`, `oraclecloud`, `ovh`, `porkbun`, `scaleway`,
`spaceship`, `timewebcloud`, `vercel`, and `vultr`. `rfc2136` is an alias for
`dnsupdate`.

The WebUI's searchable certificate-provider picker reads the runtime catalogue
and lists all these IDs alongside `local` and `custom`. This is GoDoxy's
bundled set, not the full upstream Lego catalogue.

## Cloudflare

```yaml
autocert:
  provider: cloudflare
  options:
    auth_token:
```

`auth_token` your zone API token

Follow [this guide from LEGO](https://go-acme.github.io/lego/dns/cloudflare/#api-tokens) to create a new token with required permissions

```yaml

  provider: desec

```

## OVHCloud

```yaml
autocert:
  provider: ovh
  options:
    api_endpoint:
    application_key:
    application_secret:
    consumer_key:
    oauth2_config:
      client_id:
      client_secret:
```

_Note, `application_key` and `oauth2_config` **CANNOT** be used together_

- `api_endpoint`: Endpoint URL, or one of
  - `ovh-eu`,
  - `ovh-ca`,
  - `ovh-us`,
  - `kimsufi-eu`,
  - `kimsufi-ca`,
  - `soyoustart-eu`,
  - `soyoustart-ca`
- `application_secret`
- `application_key`
- `consumer_key`
- `oauth2_config`: Client ID and Client Secret
  - `client_id`
  - `client_secret`

## Spaceship

Set `SPACESHIP_API_KEY` and `SPACESHIP_API_SECRET` in GoDoxy's environment and
reference them in the provider options. This keeps the credential values out
of the YAML file.

```yaml
autocert:
  provider: spaceship
  email: admin@example.com
  domains:
    - example.com
    - "*.example.com"
  options:
    api_key: ${SPACESHIP_API_KEY}
    api_secret: ${SPACESHIP_API_SECRET}
```

See [Lego's Spaceship DNS documentation](https://go-acme.github.io/lego/dns/spaceship/)
for the provider's credentials and settings.

## Provider credentials and options

Options depend on the provider. GoDoxy uses the provider's default config when
`options` is omitted; supply the fields it needs otherwise. YAML values can
reference GoDoxy environment variables with `${VAR}`. The CloudDNS example
below shows credentials set in `.env` and referenced from YAML options.

**CloudDNS** as an example (from [LEGO DNS documentation](https://go-acme.github.io/lego/dns/clouddns/))

### Option 1

Set these in `.env`

```bash
CLOUDDNS_CLIENT_ID=bLsdFAks23429841238feb177a572aX
CLOUDDNS_EMAIL=you@example.com
CLOUDDNS_PASSWORD=b9841238feb177a84330f
```

Reference them from `config.yml`:

```yaml
autocert:
  ...
  provider: clouddns
  options:
    client_id: ${CLOUDDNS_CLIENT_ID}
    email: ${CLOUDDNS_EMAIL}
    password: ${CLOUDDNS_PASSWORD}
```

### Option 2

Set these in `config.yml` `autocert.options` section

Turn them into:

```yaml
autocert:
  ...
  provider: clouddns
  options:
    client_id: bLsdFAks23429841238feb177a572aX
    email: you@example.com
    password: b9841238feb177a84330f
```
