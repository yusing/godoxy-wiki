## Configure a provider

Choose a provider ID from the table above. AWS Route 53 (`route53`) is not bundled,
and `googledomains` was removed in lego v5. `rfc2136` is an alias for `dnsupdate`.

Set the account email and certificate domains alongside the provider and its
options in `config/config.yml`. Option keys match the selected lego provider's
`Config` fields in snake_case, not its environment variable names. For example,
Spaceship's `APIKey` field is `api_key`, not `SPACESHIP_API_KEY`.

In the WebUI, the main and extra certificates use the same schema-generated
provider picker. Selecting any bundled DNS provider shows its concrete option
fields, including nested sections and lists. These fields come from the
provider's config type in the lego version bundled with GoDoxy.
Use the configuration references above to find the credentials your provider
requires, then use the matching `Config` field names for YAML options.

Options can be strings, booleans, numbers, arrays (such as acmedns `allow_list`),
or nested objects (such as OVH `oauth2_config`). Duration fields use Go duration
strings, for example `30s` or `1m30s`. Named maps are supported only where the
provider defines them, such as Azure's `environment.services`, whose entries
have `audience` and `endpoint` fields. HTTP transports and SDK credential objects
are excluded from editable options. Option values are redacted when GoDoxy
serializes configuration to JSON or YAML; protect the original configuration
file containing your credentials.

## Cloudflare

```yaml
autocert:
  provider: cloudflare
  options:
    auth_token:
```

`auth_token` your zone API token

Follow [this guide from LEGO](https://go-acme.github.io/lego/dns/cloudflare/#api-tokens) to create a new token with required permissions

## CloudDNS

```yaml
autocert:
  provider: clouddns
  options:
    client_id:
    email:
    password:
```

## deSEC

```yaml
autocert:
  provider: desec
  options:
    token:
```

`token` is your deSEC API token. See [LEGO deSEC DNS documentation](https://go-acme.github.io/lego/dns/desec/).

autocert:

## OVHCloud

```yaml
autocert:
  provider: ovh
  options:
    api_endpoint:
    application_key:
    application_secret:
    consumer_key:
    ttl: 120
    propagation_timeout: 1m30s
```

Alternatively, configure OAuth2 credentials as a nested object:

```yaml
autocert:
  provider: ovh
  options:
    api_endpoint:
    oauth2_config:
      client_id:
      client_secret:
```

_Note, `application_key` and `oauth2_config` **CANNOT** be used together_

- `api_endpoint`: Endpoint URL, or one of
  - `ovh-eu`,
  - `ovh-ca`,
  - `ovh-us`,
  - `kimsufi-eu`,
  - `kimsufi-ca`,
  - `soyoustart-eu`,
  - `soyoustart-ca`
- `application_secret`
- `application_key`
- `consumer_key`
- `oauth2_config`: Client ID and Client Secret
  - `client_id`
  - `client_secret`

## Porkbun

```yaml
autocert:
  provider: porkbun
  options:
    api_key:
    secret_api_key:
```

## Spaceship

```yaml
autocert:
  provider: spaceship
  email: admin@example.com
  domains:
    - example.com
    - "*.example.com"
  options:
    api_key: your-api-key
    api_secret: your-api-secret
```

See [lego's Spaceship documentation](https://go-acme.github.io/lego/dns/spaceship/)
for credential setup.

## Other bundled providers

Use the table above as the supported list. Lego's full catalogue also contains
providers that GoDoxy does not bundle. If a bundled provider fails with the
matching configuration fields and credentials, submit an issue with the provider
ID and error, without credentials.

For example, lego documents CloudDNS credentials as `CLOUDDNS_CLIENT_ID`,
`CLOUDDNS_EMAIL`, and `CLOUDDNS_PASSWORD`. In YAML, use the corresponding config
fields:

```yaml
autocert:
  provider: clouddns
  email: admin@example.com
  domains:
    - example.com
  options:
    client_id: your-client-id
    email: your-dns-account@example.com
    password: your-dns-password
```
