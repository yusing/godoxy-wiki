---
title: Inbound mTLS
description: Require HTTPS client certificates globally or per route using named trust profiles
---

Inbound mTLS makes GoDoxy verify **client certificates** during the HTTPS TLS handshake. Server certificates are still configured separately under [`autocert`](./Certificates).

## Choose Scope

| Scope | Where to Set | Behavior |
| --- | --- | --- |
| **Entrypoint-wide** | `entrypoint.inbound_mtls_profile` | Every HTTPS route requires a matching client cert. Per-route profiles cannot be set. |
| **Per-route** | `inbound_mtls_profile` on specific HTTP/HTTPS/h2c/fileserver routes (or `webui`) | Only routes with a profile require a client cert (selected by TLS SNI). `Host` and SNI must resolve to the same route (`421 Misdirected Request` otherwise). |

## 1. Define a Trust Profile

Declare reusable CA profiles at the root of `config/config.yml` (each profile requires `use_system_cas: true`, at least one `ca_files` PEM path, or both):

```yaml
inbound_mtls_profiles:
  corp:
    use_system_cas: false # Prefer a dedicated internal CA chain over the broad OS trust store
    ca_files:
      - /app/certs/corp-ca.pem
```

## 2. Apply Globally or Per Route

### Entrypoint-wide (all HTTPS)

```yaml
entrypoint:
  inbound_mtls_profile: corp
```

### Per-route (route file or Docker Compose)

```yaml
# config/config.yml
providers:
  include:
    - api.yml
```

```yaml
# config/api.yml
api.example.com:
  host: 10.0.9.98
  port: 80
  inbound_mtls_profile: corp
```

```yaml
# Docker Compose
services:
  api:
    image: myapp
    labels:
      proxy.aliases: api.example.com
      proxy.#1.port: 80
      proxy.#1.inbound_mtls_profile: corp
```

## Practical Notes

- A missing or untrusted client certificate fails during the **TLS handshake** (no HTTP response is returned).
- Go's TLS stack does not perform CRL/OCSP revocation checks here.
- After rotating CA files on disk, **reload or restart** GoDoxy so the CA trust pools rebuild.
