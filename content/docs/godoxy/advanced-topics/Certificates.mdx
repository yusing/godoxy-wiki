GoDoxy manages TLS certificates via [`lego`](https://github.com/go-acme/lego) (ACME DNS-01) or loads static certificate files you already manage (`provider: local`). You can configure a primary certificate plus any number of `extra` certificates selected automatically by **TLS SNI**.

## How SNI Certificate Selection Works

During the TLS handshake, GoDoxy picks a certificate in this order:

1. **Exact domain match** beats **wildcard match** (`app.example.com` beats `*.example.com`).
2. **Main certificate** beats **`extra` certificates** when both match.
3. **Fallback**: If nothing matches, GoDoxy serves the main certificate.

### Automatic Renewal (ACME)

GoDoxy checks certificates automatically and renews (with a 1-hour retry cooldown on failure) whenever:
- `autocert` is enabled and no certificate file exists yet
- `autocert.domains` no longer matches the loaded certificate's SANs
- The certificate expires within **30 days**

## Common Setups

### 1. Automatic Wildcard Certificate (DNS-01, e.g. Cloudflare)

```yaml
autocert:
  provider: cloudflare
  email: you@example.com
  domains:
    - "*.yourdomain.com"
  # certificate_key_type: RSA2048  # optional; default EC256 (use RSA* for legacy/IoT clients)
  options:
    auth_token: ${CF_API_TOKEN}
```

See [DNS-01 Providers](../getting-started/DNS-01-Providers) for all bundled providers and option names.

### 2. Bring Your Own Certificate (`provider: local`)

```yaml
autocert:
  provider: local
  cert_path: certs/cert.crt  # relative to /app
  key_path: certs/priv.key
```

<Callout type="info">
  With `provider: local`, SNI matching reads the certificate's own Common Name
  (CN) and SANs — the `domains` field is ignored and no ACME requests are made.
</Callout>

### Custom Internal ACME CA

Download your internal CA root bundle (e.g. `step-ca`) into `certs/` (mounted at `/app/certs`):

```shell
export ACME_URL=https://acme.internal
curl -k ${ACME_URL}/roots.pem > certs/roots.pem
```

```yaml
autocert:
  provider: custom
  email: you@example.com
  domains:
    - "*.yourdomain.com"
  ca_dir_url: https://acme.internal/acme/acme/directory
  ca_certs:
    - certs/roots.pem
  # Optional: External Account Binding (EAB)
  # eab_kid: your-eab-kid
  # eab_hmac: base64-encoded-hmac
```

### 4. Multiple Certificates with SNI (`extra`)

Add additional certificates under `autocert.extra`. Each entry must use a unique `cert_path` and `key_path`, inherits unspecified fields (`provider`, `email`, `options`, `certificate_key_type`) from the main block, and renews independently:

```yaml
autocert:
  provider: cloudflare
  email: you@example.com
  domains:
    - "*.example.com"
  options:
    auth_token: ${CF_API_TOKEN}
  extra:
    # Same provider, second domain
    - cert_path: certs/other.crt
      key_path: certs/other.key
      domains:
        - "*.other.com"

    # Custom internal CA
    - cert_path: certs/internal.crt
      key_path: certs/internal.key
      provider: custom
      domains:
        - "*.internal.local"
      ca_dir_url: https://ca.internal/acme/directory

    # Static local cert (SNI matches CN/SAN in static.crt)
    - cert_path: certs/static.crt
      key_path: certs/static.key
      provider: local
```

## TCP Stream Routes on the HTTPS Listener

TCP routes bound to the shared `HTTPS_ADDR` (`:443`) share the TLS socket with HTTP routes and are selected by **ClientHello SNI** (short alias or FQDN):

- **TLS Passthrough (default)**: Encrypted bytes are forwarded directly to `host:port` without decrypting. Use this when the upstream serves its own TLS certificate.
- **TLS Termination (`tls_termination: true`)**: GoDoxy completes TLS using `autocert` and forwards a **plaintext** TCP stream to `host:port`. Only allowed on TCP routes sharing `HTTPS_ADDR` when `autocert` is configured.

## Configuration Reference

| Field | Type | Default | Required | Description |
| --- | --- | --- | --- | --- |
| `provider` | string | `local` | Yes | DNS-01 provider ID, `custom`, or `local` |
| `email` | string | — | ACME only | ACME account email |
| `domains` | string[] | — | ACME only | Domains for ACME cert issuance (ignored for `local`) |
| `options` | object | — | Provider-dependent | LEGO provider `Config` fields in `snake_case` (supports `${VAR}`) |
| `resolvers` | string[] | — | No | Custom DNS resolvers for propagation checks (e.g. `1.1.1.1:53`) |
| `cert_path` | string | `certs/cert.crt` | No | Certificate file path |
| `key_path` | string | `certs/priv.key` | No | Private key file path |
| `extra` | object[] | — | No | Additional certificates for SNI selection |
| `ca_dir_url` | string | — | `custom` only | Custom ACME directory URL |
| `ca_certs` | string[] | — | No | Extra CA root certificates for the ACME server |
| `eab_kid` | string | — | No | External Account Binding Key ID |
| `eab_hmac` | string | — | No | Base64-encoded External Account Binding HMAC |
| `certificate_key_type` | string | `EC256` | No | ACME leaf key type: `EC256`/`P256`, `EC384`/`P384`, `RSA2048`/`2048`, `RSA3072`/`3072`, `RSA4096`/`4096`, `RSA8192`/`8192` |

## Troubleshooting

- **CNAME on `_acme-challenge`**: Set `LEGO_DISABLE_CNAME_SUPPORT=1` in `.env`.
- **Stale local DNS cache**: Configure public resolvers under `autocert.resolvers` (e.g. `["1.1.1.1:53", "8.8.8.8:53"]`).
- See [Troubleshooting & FAQ](../Troubleshooting#certificates--tls) for more certificate issues.
