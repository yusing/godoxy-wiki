---
title: Health Monitoring
description: How GoDoxy combines Docker healthchecks, fallback probes, exclusions, and maintenance silence windows
---

GoDoxy monitors the health of **every route by default**, including containers excluded from proxying.

## How Checks Work

1. **Docker `HEALTHCHECK` first**: If a container defines a Docker healthcheck (in its `Dockerfile` or `compose.yml`), GoDoxy treats Docker's status as authoritative and does **not** send its own HTTP/TCP probe (`path` and `use_get` are ignored).
2. **GoDoxy fallback probe**: If no Docker healthcheck exists (or Docker cannot be queried due to an API/timeout error), GoDoxy probes the upstream directly:

| Route Type | Probe Method | Healthy | Unhealthy |
| --- | --- | --- | --- |
| **HTTP / HTTPS** | `HEAD` (or `GET` if `use_get: true`) to `path` (default `/`) | Any non-5xx HTTP response | Connection error or 5xx |
| **TCP / UDP** | Dials upstream socket | Connection established | Connection fails |
| **File Server** | `os.Stat` on `root` directory | Directory exists and is readable | Otherwise |

## Disabling Health Probes

- **Single route (route file or Docker label)**: Set `healthcheck.disable: true` (`proxy.#1.healthcheck.disable: true`).
- **All routes of a Docker container**: Use `proxy.exclude`:

| Label Value | Proxying | GoDoxy Fallback Probe | Docker `HEALTHCHECK` |
| --- | --- | --- | --- |
| `false` (default) | Enabled | Enabled | Enabled |
| `true` or `proxy` | Disabled | Enabled | Enabled |
| `healthcheck` | Enabled | Disabled | Enabled |
| `proxy,healthcheck` or `all` | Disabled | Disabled | Enabled |

## Property Reference

| Property | Description | Default | Values |
| --- | --- | --- | --- |
| `disable` | Disable GoDoxy fallback probing (Docker healthcheck remains) | `false` | boolean |
| `path` | Probe path (**HTTP only**) | `/` | Relative URI (e.g. `/health`) |
| `use_get` | Use `GET` instead of `HEAD` (**HTTP only**) | `false` | boolean |
| `interval` | Time between probes | `5s` | Go duration |
| `timeout` | Per-probe timeout | `5s` | Go duration |
| `retries` | Consecutive failures before alerting unhealthy | `15s / interval` | integer |
| `silence` | Daily local-time windows suppressing "service down" alerts | empty | List of `HH:MM-HH:MM` |

## Silence Windows

Suppress "service down" notifications during recurring maintenance (such as nightly backups) while keeping health checks running:

```yaml
# Global default in config/config.yml
defaults:
  healthcheck:
    silence:
      - 02:00-04:30
      - 23:30-00:30 # Midnight-crossing windows are supported
```

```yaml
# Per-route override (route file) — replaces global default; use [] to opt out
app:
  healthcheck:
    silence: [02:00-04:30]

# Docker label (use "[]" to opt out of global silence windows)
proxy.#1.healthcheck.silence: 02:00-04:30, 23:30-00:30
```

- Uses the GoDoxy container's local timezone — set `TZ` in `.env` (e.g. `TZ=America/New_York`).
- Use two-digit 24-hour times (`02:00`, not `2:00`). On DST spring-forward, a window inside the skipped hour is skipped that day.
- If a service is still down when the window ends, the alert fires on the next check. If it goes down and recovers inside the window, no alert is sent; if a down alert was already sent before the window, recovery still sends an "up" notification.
- In the WebUI route editor, clear **Use default silence windows** to customize or opt out for a single route.
