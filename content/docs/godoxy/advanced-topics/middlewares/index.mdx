Middlewares inspect or transform HTTP/HTTPS traffic globally on the entrypoint or per route. Middleware names and option keys are **case-insensitive** and snake/camel-agnostic (`redirectHTTP`, `redirect_http`, and `RedirectHttp` are equivalent).

## Built-in Middleware Catalog

| Category | Middleware | What It Does |
| --- | --- | --- |
| **Access Control** | [CIDR Whitelist](access-control/CIDR-Whitelist) (`cidr_whitelist`) | Allow only listed IPs, CIDRs, `host:<name>`, or `set:<name>` |
| | [Rate Limiter](access-control/Rate-Limiter) (`rate_limit`) | Limit requests per client (`average`, `burst`, `periods`) |
| **Auth & Security** | [OIDC](authentication-and-security/OIDC) (`oidc`) | Protect routes with OpenID Connect (global or per-app issuer) |
| | [Forward Auth](authentication-and-security/Forward-Auth) (`forward_auth`) | Delegate auth to an external service (e.g. TinyAuth, Authelia) |
| | [CrowdSec AppSec](authentication-and-security/Crowdsec-AppSec) (`crowdsec`) | Inspect requests against CrowdSec AppSec WAF |
| | [hCaptcha](authentication-and-security/hCaptcha) (`hcaptcha`) | Gate routes behind a per-session hCaptcha challenge |
| **IP Resolution** | [Cloudflare Real IP](ip-resolution/Cloudflare-Real-IP) (`cloudflare_real_ip`) | Resolve client IP from `CF-Connecting-IP` (recommended on entrypoint) |
| | [Real IP](ip-resolution/Real-IP) (`real_ip`) | Resolve client IP from a custom header and trusted proxy list |
| **Headers & Paths** | [Modify Request](request-response-modification/Modify-Request) (`modify_request` / `request`) | Set/add/hide request headers and add path prefixes |
| | [Modify Response](request-response-modification/Modify-Response) (`modify_response` / `response`) | Set/add/hide response headers (e.g. security & CORS headers) |
| | [X-Forwarded Headers](request-response-modification/X-Forwarded-Headers) (`hide_x_forwarded` / `set_x_forwarded`) | Strip or override `X-Forwarded-*` headers |
| **Content** | [Modify HTML](content-modification/Modify-HTML) (`modify_html`) | Append or replace HTML elements by CSS selector |
| | [Themed](content-modification/Themed) (`themed`) | Inject preset dark themes, Google Fonts, or Theme Park CSS |
| **Traffic Control** | [Redirect HTTP](traffic-control/Redirect-HTTP) (`redirect_http`) | Redirect HTTP (`:80`) traffic to HTTPS (`:443`) |
| | [Custom Error Pages](traffic-control/Custom-Error-Pages) (`custom_error_pages`) | Serve custom HTML error pages (enabled on entrypoint by default) |

## Where & How to Configure Middlewares

| Location | Execution Order | YAML Shape | Best For |
| --- | --- | --- | --- |
| **Entrypoint** (`config/config.yml`) | Ordered (list) | `- use: <name>` | Global policies (`CloudflareRealIP`, `RedirectHTTP`, global `oidc`) |
| **Middleware Compose** (`config/middlewares/*.yml`) | Ordered (list) | `<preset>:\n  - use: <name>` | Reusable bundles referenced via `<preset>@file` |
| **Route Files** (`config/*.yml`) | Unordered (use `priority`) | `middlewares:\n  <name>:` | Non-Docker per-route rules |
| **Docker Labels** (`compose.yml`) | Unordered (use `priority`) | `proxy.#1.middlewares.<name>:` | Container per-route rules |

<Callout type="info">
  In Docker Compose labels, escape runtime variables like `$remote_host` as
  `$$remote_host` so Compose does not strip them before Docker sees the label.
  Route files (`config/*.yml`) use a single `$`.
</Callout>

### Side-by-Side Syntax

```yaml
# 1. Entrypoint (config/config.yml) — ordered list with `- use:`
entrypoint:
  middlewares:
    - use: CloudflareRealIP
    - use: CIDRWhitelist
      allow:
        - 127.0.0.1
        - 192.168.0.0/16

# 2. Middleware Compose (config/middlewares/whitelist.yml) — reusable named list
myWhitelist:
  - use: CloudflareRealIP
  - use: CIDRWhitelist
    allow:
      - 127.0.0.1
      - 192.168.0.0/16

# 3. Route File (config/services.yml) — map keyed by middleware name
myapp:
  middlewares:
    myWhitelist@file: # Reuse the composition above
    cidr_whitelist:
      priority: 2
      allow: [10.0.0.0/8]

# 4. Docker Labels (compose.yml) — flat or inline YAML block
services:
  app:
    labels:
      proxy.#1.middlewares.myWhitelist@file:
      proxy.#1.middlewares.redirect_http.priority: 1
      proxy.#1.middlewares.cidr_whitelist: |
        priority: 2
        allow:
          - 127.0.0.1
          - 192.168.0.0/16
```

## Bypass Rules

Every middleware accepts a `bypass` list using [Rule Conditions](../rule-based-routing/Conditions) to skip that middleware for specific routes, paths, or client IPs:

```yaml
# Entrypoint example
entrypoint:
  middlewares:
    - use: oidc
      bypass:
        - route pocket-id
        - route immich & path glob(/api/*)
        - remote 192.168.0.0/16
```

```yaml
# Route file example
myapp:
  middlewares:
    oidc:
      bypass:
        - path glob(/api/*)
        - remote 192.168.0.0/16
```

## Entrypoint Overlay Promotion

If a middleware (such as `oidc` or `cidr_whitelist`) is already active on `entrypoint.middlewares`, you can add **per-route bypass rules** without duplicating or re-evaluating the middleware:

```yaml
# config/config.yml
entrypoint:
  middlewares:
    - use: oidc

# Docker label (or route file) containing ONLY `bypass`
proxy.myapp.middlewares.oidc.bypass: |
  - path glob(/public/*)
  - path /health
```

**How it works:**
1. When a route-local middleware entry contains **only `bypass`** and matches an entrypoint middleware name, GoDoxy promotes those bypass rules into the entrypoint middleware (scoped to that route) and consumes the route-local entry so it does not run twice.
2. If the route-local entry includes any option besides `bypass` (for example `allowed_groups`), it is **not** promoted — it runs as a separate route middleware in addition to the entrypoint middleware.
